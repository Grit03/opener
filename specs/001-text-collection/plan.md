# 번역할 본문 수집 구현 계획

## 목표

현재 문서에서 번역 후보가 되는 영어 본문을 읽는 순서대로 수집한다. 결과는 다음 기능에서 원문 아래 표시 위치를 찾을 수 있어야 하며, 수집 중에는 DOM을 변경하지 않는다.

## 기술 환경

- WXT 콘텐츠 스크립트
- TypeScript
- 브라우저 DOM API
- Vitest Browser Mode와 Chromium
- 새 의존성 없음

## 설계

### 수집 결과

각 수집 단위는 식별자, 정리된 텍스트, 원본 위치를 가리키는 요소를 가진다. 결과는 배열로 반환해 문서 순서를 유지한다. 한 번의 수집에서 같은 원본 위치와 구간은 한 번만 포함한다.

### 본문 선택

1. `main`과 주 콘텐츠 역할을 가진 영역을 우선한다.
2. 없으면 `article`, 마지막으로 `body`를 사용한다.
3. 같은 우선순위의 영역이 여러 개면 문서 순서대로 처리한다.
5. 선택한 영역이 서로 중첩되면 안쪽 영역을 다시 수집하지 않는다.

### 탐색과 묶기

1. 선택한 영역의 텍스트 노드를 위에서 아래로 탐색한다.
2. 제목, 문단, 목록 항목, 표의 칸과 블록 요소를 수집 경계로 삼는다.
3. 줄바꿈과 중첩 블록을 만나면 현재 묶음을 끝낸다.
4. 링크, 강조 요소와 짧은 인라인 코드는 주변 텍스트와 함께 묶는다.
5. 공백을 정리한 뒤 내용이 없는 묶음은 버린다.
6. 블록 여부는 기존 `isBlock` 판정을 사용한다. `isBlock`에 판정될 때 사용하는 block 엘리먼트들을 MDN 등 DOM 관련 공식 문서를 바탕으로 수집하여 보완해도 좋다.

### 제외 판정

탐색 전에 다음 조건을 확인하고 해당 영역의 내부를 건너뛴다.

- 문서 정보와 실행 코드
- 입력 요소와 편집 가능한 영역
- 숨겨진 영역
- 번역 금지 영역
- 코드 블록
- 별도 문서와 비문자 콘텐츠

숨김 여부는 요소 속성, 조상의 표시 상태, 텍스트가 실제로 차지하는 영역을 함께 확인한다. 언어는 가장 가까운 조상의 유효한 언어 표시를 사용한다. 영어는 포함하고 다른 언어는 제외하며, 표시가 없으면 후보로 둔다.

### 원문 보호

수집 함수는 읽기 작업만 수행한다. 속성 추가, 요소 삽입, 텍스트 교체, 이벤트 등록은 하지 않는다. 원본 요소 참조는 결과에만 보관한다.

## 파일 변경

- `apps/extension/utils/text-collection.ts`
  - 수집 결과 형식
  - 본문 선택
  - 제외·언어·숨김 판정
  - 텍스트 탐색과 묶기
- `apps/extension/tests/text-collection.test.ts`
  - 기능 요구사항과 완료 조건 검증
- `apps/extension/utils/layout.ts`
  - 기존 판정을 그대로 사용하며 필요한 경우에만 작은 보완

콘텐츠 스크립트 연결과 화면 표시는 이번 변경에 포함하지 않는다.

## 검증

브라우저 테스트에서 다음을 확인한다.

1. 본문 선택 우선순위와 문서 순서
2. 문단, 목록, 표, 줄바꿈의 경계
3. 링크와 인라인 코드가 포함된 문장
4. 입력, 숨김, 번역 금지, 코드 블록 제외
5. 영어, 다른 언어, 언어 표시가 없는 영역의 구분
6. 중복 없는 결과와 원문 DOM 보존

마지막으로 타입 검사, 린트와 전체 단위 테스트를 실행한다.
