# 번역할 본문 수집 구현 계획

## 목표

현재 문서의 영어 본문에서 번역할 텍스트만 DOM 순서대로 모은다. 제목·문단·목록 항목·표의 칸은 각각 나누고, 문장 안의 링크와 강조 문구는 함께 묶는다. 이후 결과를 표시할 위치를 찾을 수 있도록 원본 요소와 텍스트 노드의 참조를 반환한다. 원문 DOM은 변경하지 않는다.

## 기술 환경

- WXT 콘텐츠 스크립트에서 사용할 TypeScript 유틸리티
- 브라우저 표준 DOM·CSSOM API
- Vitest Browser Mode로 실제 브라우저에서 단위 테스트 실행
- 새 의존성 없음

## 번역할 텍스트와 함께 반환할 정보

본문 요소는 번역할 텍스트를 찾을 범위로 선택한 `main`, `article`, `body`를 뜻한다. 모은 글마다 다음 정보를 반환한다.

- 공백을 정리한 텍스트
- 기준 요소: 텍스트를 감싸는 요소 중 제목·문단 등의 역할이나 CSS 배치 때문에 글을 나누는 가장 가까운 요소. 본문 요소 안에 해당하는 요소가 없으면 본문 요소를 사용한다. `br`로 나눈 글들은 같은 기준 요소를 가질 수 있다.
- 내용을 구성한 원본 텍스트 노드 목록

번역 텍스트를 모으는 공개 함수는 호출할 때마다 새 결과 배열을 만든다. 이전 실행 결과를 보관하거나 새 결과에 누적하지 않는다.

## 처리 흐름

### 1. 본문 선택

`main`에서 먼저 번역할 텍스트를 찾고, 모을 글이 없으면 `article`, `body` 순서로 넘어간다. 같은 태그가 중첩돼 있으면 바깥 요소에서만 탐색을 시작한다. 여러 요소에서 글을 모을 때도 DOM 순서를 유지한다.

### 2. 순서대로 탐색

`TreeWalker`로 요소와 텍스트 노드를 DOM 순서대로 탐색한다. 코드 블록이나 입력 영역처럼 전체를 제외할 요소에서는 자식 탐색도 멈춘다. 인라인 `span`처럼 글을 감싸기만 하는 요소는 안쪽 글까지 계속 탐색한다.

### 3. 번역하지 않을 글 제외하기

다음 영역의 글은 번역할 텍스트에 포함하지 않는다. 해당 요소와 그 안의 모든 내용을 건너뛴다.

- 문서 정보와 실행 코드
- 입력 요소와 편집 가능한 영역
- `pre`와 블록으로 표시되는 `code`
- 프레임, 임베드, 그래픽과 미디어 콘텐츠

`translate`, 언어와 표시 여부는 텍스트 노드마다 판단한다. 자식 요소에 `translate="yes"`나 `visibility: visible`이 지정되면 안쪽 글은 번역할 텍스트에 포함될 수 있으므로, 부모 상태만 보고 자식 탐색을 중단하지 않는다.

`display: contents`인 요소는 자체 레이아웃 박스를 만들지 않지만 안쪽 글은 표시될 수 있다. 이 요소에 박스가 없다는 이유로 안쪽 글까지 제외하지 않는다.

숨김 여부는 텍스트를 감싸는 요소 중 `display: contents`가 아닌 가장 가까운 요소의 `checkVisibility()`로 확인한다. `opacity`와 `visibility`도 함께 검사한다. 남은 텍스트는 `Range.getClientRects()`로 너비와 높이가 있는 영역이 있는지 확인한다. 단, `content-visibility: auto` 아래의 글은 화면 밖에서 그리기가 생략될 수 있으므로, 영역이 없다는 이유만으로 제외하지 않는다.

### 4. 언어 판정

텍스트를 감싸는 요소 중 `lang` 속성이 있는 가장 가까운 요소를 찾고, 그 값을 `Intl.Locale`로 검사한다. `en`, `en-US` 등 영어로 표시된 글은 번역할 텍스트로 모으고, 유효한 다른 언어로 표시된 글은 제외한다. `lang`이 없거나 비어 있거나 값을 해석할 수 없으면, 언어를 모른다는 이유만으로 번역할 글에서 제외하지 않는다.

### 5. 글을 묶고 나누기

- 제목, 문단, 목록 항목, 용어와 설명, 표 제목과 각 칸을 각각 따로 모은다.
- 목록 항목 안에 문단이 있으면, 그 문단은 목록 항목의 나머지 글과 따로 모은다. 안쪽 문단의 글을 바깥 항목에 중복해서 넣지 않는다.
- `br`을 만나면 앞뒤 글을 나눈다. 제목·문단 등의 역할이 없는 요소는 계산된 `display`를 확인해, 블록 배치이면 앞뒤 글을 나눈다.
- 링크, 강조와 인라인 코드는 주변 텍스트와 합친다.
- 텍스트 노드의 문자열을 먼저 이어 붙인 뒤 공백을 정리하고 빈 결과를 버린다.

## 파일 변경

- `apps/extension/utils/text-collection.ts`
  - 번역할 글과 원문 위치를 담는 타입, 번역 텍스트를 모으는 공개 함수 구현
  - 본문 선택, DOM 탐색, 제외할 영역과 언어 확인, 글 묶기와 분리
  - CSS 배치 판정은 비공개 함수로 레이아웃 구역에 모은다.
- `apps/extension/tests/text-collection.test.ts`
  - 번역 텍스트를 모으는 공개 함수의 반환값으로 요구사항을 검증한다.
  - 단위 테스트로 문단·줄바꿈·CSS 기반으로 맞게 글을 나누는지, 숨겨지거나 다시 표시된 글을 번역할 텍스트에 올바르게 포함하거나 제외하는지 확인한다.
  - 비공개 함수는 직접 호출하지 않고, 번역 텍스트를 모으는 공개 함수의 결과로 함께 검증한다.

콘텐츠 스크립트 연결, 결과 표시와 동적 변경 감지는 이번 범위에 포함하지 않는다.

## TDD 순서

아래 기능 순서대로 **테스트 작성 → 예상한 실패 확인 → 최소 구현 → 통과 확인**을 반복한다. 이미 지원되는 동작의 테스트는 통과 상태를 유지하며, 실패를 만들려고 기존 코드를 고치지 않는다.

1. 본문 선택, DOM 순서, 원본 참조, 반복 호출과 원문 보존
2. 제목·문단·목록·표·줄바꿈과 CSS 배치에 따른 분리, 문장 안의 글 묶기
3. 입력·편집·코드·번역 금지 영역 제외
4. 글이 표시되는지 확인해 번역할 텍스트에 포함하거나 제외하기
5. `lang`에 따른 영어 포함과 다른 언어 제외

모든 테스트가 통과하면 이름과 중복을 정리하고, 전체 검사로 마무리한다.
