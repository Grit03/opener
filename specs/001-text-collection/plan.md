# 번역할 본문 수집 구현 계획

## 목표

현재 문서에서 영어 본문을 읽는 순서와 의미 경계에 맞춰 수집한다. 이후 결과 표시 기능이 원문 위치를 찾을 수 있도록 참조를 반환하되, 페이지 DOM은 변경하지 않는다.

## 기술 환경

- WXT 콘텐츠 스크립트에서 사용할 TypeScript 유틸리티
- 브라우저 표준 DOM·CSSOM API
- Vitest Browser Mode와 Chromium
- 새 의존성 없음

## 수집 결과

각 결과는 다음 정보를 가진다.

- 공백을 정리한 텍스트
- 결과를 붙일 기준 요소
- 내용을 구성한 원본 텍스트 노드 목록

수집 함수는 호출할 때마다 새 결과 배열을 만든다. 이전 실행 결과를 보관하거나 새 결과에 누적하지 않는다.

## 처리 흐름

### 1. 본문 선택

읽을 수 있는 최상위 `main`, 최상위 `article`, `body` 순서로 수집 범위를 선택한다. `display: contents`는 자식의 표시 상태를 확인한다. 같은 단계에 여러 후보가 있으면 문서 순서를 유지하고, 중첩된 후보는 바깥쪽만 사용한다.

### 2. 순서대로 탐색

`TreeWalker`로 요소와 텍스트 노드를 함께 탐색한다. 제외할 요소에서는 하위 탐색을 멈추고, 의미 없는 래퍼는 자식 탐색을 계속한다. 여러 본문 범위를 처리할 때도 최종 결과는 문서 순서를 유지한다.

### 3. 제외 판정

다음 영역은 하위 트리 전체를 건너뛴다.

- 문서 정보와 실행 코드
- 입력 요소와 편집 가능한 영역
- `translate` 값이 `false`인 영역
- `pre`와 블록으로 표시되는 `code`
- 프레임, 임베드, 그래픽과 미디어 콘텐츠
- 실제로 표시되지 않는 영역

숨김 여부는 `display: contents`가 아닌 가장 가까운 요소의 `checkVisibility()`로 먼저 확인한다. `opacity`와 `visibility`도 함께 검사한다. `content-visibility: auto`로 화면 밖 렌더링이 생략된 경우는 제외하지 않는다. 남은 텍스트는 `Range`의 실제 크기를 보조 조건으로 확인한다.

### 4. 언어 판정

가장 가까운 `lang`을 `Intl.Locale`로 검사한다. 영어와 영어 지역 태그는 포함하고, 유효한 다른 언어는 제외한다. 언어 표시가 없거나 알 수 없으면 후보로 남긴다.

### 5. 단위 묶기

- 제목, 문단, 목록 항목, 용어 설명과 표의 각 칸을 의미 경계로 사용한다.
- 중첩된 의미 경계에서는 가장 안쪽 경계가 자신의 텍스트를 맡는다.
- `br`과 의미 없는 블록 배치를 만나면 현재 단위를 끝낸다.
- 링크, 강조와 인라인 코드는 주변 텍스트와 합친다.
- 텍스트 노드의 문자열을 먼저 이어 붙인 뒤 공백을 정리하고 빈 결과를 버린다.

콘텐츠 스크립트 연결, 결과 표시와 동적 변경 감지는 이번 범위에 포함하지 않는다.

## TDD 순서

1. 본문 선택과 문서 순서 테스트를 작성하고 실패를 확인한다.
2. 의미 경계, 링크와 줄바꿈 테스트를 작성하고 실패를 확인한다.
3. 계산된 `display`의 경계 테스트를 작성하고 실패를 확인한다.
4. 입력, 편집, 코드와 `translate` 제외 테스트를 작성하고 실패를 확인한다.
5. 숨김 상태와 실제 텍스트 영역 테스트를 작성하고 실패를 확인한다.
6. 언어, 반복 호출과 DOM 보존 테스트를 작성하고 실패를 확인한다.
7. 각 단계에서 해당 테스트를 통과시키는 최소 구현만 추가한다.
8. 모든 테스트가 통과한 뒤 이름과 중복을 정리한다.
